# Постоянен APK подпис

Текущата сесия няма достъп до GitHub Secrets (`Forbidden`). Докато не бъдат зададени, CI използва временния Android debug ключ и обновяване върху стар APK не е гарантирано.

Създай и запази постоянен ключ на доверен компютър:

```sh
keytool -genkeypair -keystore fitlens-signing.jks -alias fitlens -keyalg RSA -keysize 3072 -validity 10000
```

Командата пита за пароли и име. Не включвай лична информация, ако не желаеш тя да присъства в сертификата. Запази файла и паролите в сигурно резервно копие. Не ги добавяй в Git.

В GitHub → repository Settings → Secrets and variables → Actions добави:

- `FITLENS_KEYSTORE_BASE64`: base64 съдържанието на файла (`base64 -w0 fitlens-signing.jks` на Linux).
- `FITLENS_KEYSTORE_PASSWORD`: паролата за keystore.
- `FITLENS_KEY_ALIAS`: `fitlens`.
- `FITLENS_KEY_PASSWORD`: паролата за ключа.

Следващият CI build автоматично използва този ключ. При наличен файл и липсваща друга настройка pipeline спира, вместо да смени подписа тихо. `versionCode` е 1000 + номера на изпълнението на Android workflow.

Това не възстановява стар временен debug ключ. Първото преминаване към постоянния подпис може да изисква деинсталиране. То изтрива локални данни; тази версия все още няма пълен износ/възстановяване на настройките. Не деинсталирай, преди да си запазил необходимите данни.
